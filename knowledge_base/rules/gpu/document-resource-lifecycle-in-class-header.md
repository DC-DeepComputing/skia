description: When declaring GPU resource and atlas managers or adding them to coordinators like AtlasProvider, document lifecycles, allocation, and deduplication models
rubric: readability
severity: nit
---

**Rule.** When introducing or modifying GPU resource, atlas, or buffer managers
that employ multi-page allocation, capacity growth, page flip-flopping, or
progressive eviction across flushes, document the complete lifecycle in the
class header documentation rather than solely in internal .cpp comments.
Explicitly describe how pages or slots are allocated, when allocations grow or
fail, and when older resources are retired, retained, or uploaded during flush
and draw boundaries. Additionally, when declaring specialized atlas or manager
members in coordinator classes (such as AtlasProvider), document each member
variable with a comment describing the assets it manages and its allocation and
deduplication strategy.

**Why.** GPU resource and atlas managers coordinate complex state transitions
across client draw context flushes. Placing lifecycle, allocation growth, and
retirement semantics in class headers and documenting coordinator member fields
gives callers and maintainers a clear architectural contract of asset ownership
and deduplication without forcing them to reverse-engineer lifetimes from
internal method implementations.

## Examples

Bad:

```cpp
// AlphaAtlasManager.h
class AlphaAtlasManager {
public:
    AlphaAtlasManager(Recorder* recorder);
    uint8_t* requestAlphaSpace(int32_t numBytes);
    void recordUploads(DrawContext* dc);
    ...
};

// AtlasProvider.h
#if defined(SK_ENABLE_SPARSE_STRIPS)
    std::unique_ptr<AlphaAtlasManager> fAlphaAtlasManager;
#endif
```

Good:

```cpp
// AlphaAtlasManager.h
// Holds CPU-side alpha values from strip rasterization and manages texture allocation.
// Uses a two-page system: when the first page is exhausted, a second page is created
// with double capacity. Uploads occur on DrawContext flush; if both pages are active,
// the older page is retired and the larger page becomes the primary page.
class AlphaAtlasManager {
public:
    AlphaAtlasManager(Recorder* recorder);
    uint8_t* requestAlphaSpace(int32_t numBytes);
    void recordUploads(DrawContext* dc);
    ...
};

// AtlasProvider.h
#if defined(SK_ENABLE_SPARSE_STRIPS)
    // Handles the allocation and uploading of the alpha values generated by sparse strip
    // rasterization, using a growing system. Currently, performs no deduplication.
    std::unique_ptr<AlphaAtlasManager> fAlphaAtlasManager;
#endif
```
